# 局域网设备互联

本页介绍 Android 版“附近的弥乐”及其 LAN 协议概念。Windows/Linux 的协议实现和可用功能以各自版本说明为准；不要假设所有平台都已实现相同模式。参与设备需要运行兼容版本，并处于可互相访问的网络环境；这些功能不通过互联网中继，也不能跨越通常的 NAT/访客网络隔离。

## 选择合适的模式

- **控制**：在本机控制另一台弥乐设备的播放、进度或音量；音频仍由被控设备自行解析和播放。
- **投放（Cast）**：本机将弥乐当前播放链路中的 PCM 音频送到接收设备。传送的是弥乐自己的播放音频，不会录制其他应用的系统声音；投放时主要由接收端出声。
- **传输（Transfer）**：把曲目或队列交给另一台设备，由接收设备使用自己的账号和音源重新解析。若接收端没有该曲目来源或权限，可能无法播放。
- **一起放（Together）**：多台设备协调播放同一队列和进度。网络延迟、音频设备时钟与设备性能会造成位置差异，不保证声学上的严格同步。

这与网易云音乐的“**一起听**”房间不是同一功能：LAN 一起放是弥乐设备之间的局域网会话；网易云一起听由网易云服务管理房间和参与者，需要网易云账号及互联网连接。

## 连接前检查

- 设备连接到同一 Wi-Fi 或可互通的局域网；访客网络、客户端隔离或 VPN 可能阻断设备发现。
- Android 系统允许弥乐使用所需的附近设备/网络权限。
- 设备保持亮屏或允许弥乐在后台运行，以便维持连接。
- 如使用 VPN，确认它不会把设备隔离在不同虚拟网络中。

## 发现、配对与信任

在“设置 → LAN playback/局域网播放”查看本机配对 PIN、控制端口和最近连接设备；再从“附近的弥乐”开始发现、连接并选择需要的模式。首次连接输入接收端显示的 PIN。连接后只有在本机明确加入“常用设备”列表，后续才可免 PIN 连接；单次成功配对不等于永久信任。

连接服务默认控制端口为 47831；若被占用会尝试之后的九个端口，并在界面报告实际端口。设备发现使用局域网广播，路由器客户端隔离、防火墙或 VPN 可能阻断发现/控制。

一起放由会话发起方控制队列和切歌，加入的设备按协调时刻开始播放；迟到设备不保证追赶到同一毫秒位置。曲目资源、设备解码和网络延迟不同，可能造成听感偏差。

## 配对与安全

配对 PIN 用于阻止同网段陌生设备直接建立未授权会话；“常用设备”是本机保存的信任便利设置，不是强密码学身份认证。不要在不可信的公共网络中开放 LAN 播放服务。移除不再使用的常用设备，并在不需要发现/远程控制时关闭 LAN 播放设置。

## 无法连接时

若无法发现设备，先确认设备在同一个可互通的局域网；若能发现但连接失败，核对 PIN、设备信任状态和实际控制端口。特定路由器或系统防火墙可能阻止发现或连接。

若控制可用但没有声音，确认选择的模式：控制不传音频，传输会让接收端重新解析歌曲，Cast 才会传输当前播放的 PCM。还需确认接收设备未静音并且输出设备可用。
