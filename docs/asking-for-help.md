# 如何有效反馈问题

一份清晰的问题报告能帮助维护者更快复现和定位问题，也能让遇到相同情况的用户找到答案。这里把开源社区的提问建议整理成适用于弥乐的简明模板。

> **本页是提问指南，不是技术支持服务本身。** 请通过弥乐项目的 [GitHub Issues](https://github.com/lladlam/MeloX-Android/issues) 或项目公布的社区渠道反馈；本指南原作者不负责弥乐的支持。

本页参考并改写自 [《提问的智慧》中文指南](https://github.com/ryanhanwu/How-To-Ask-Questions-The-Smart-Way/blob/main/README-zh_CN.md)，原文著作权与译者信息请见上游页面。这里只保留和弥乐用户反馈最相关的实践，并补充弥乐版本、设备输出和日志要求。

## 提问前先做这几步

1. 查看[常见问题](faq)和[故障排查](troubleshooting)。
2. 在项目 Issues 中搜索关键词，看看是否已有相同问题。
3. 更新到当前正式版后重试；如果问题只发生在开发版，也请明确说明。
4. 尽量缩小复现范围，例如确认是单首歌曲、某一音源，还是所有播放都失败。
5. 记录具体操作和现象，不要只写自己的原因猜测。

无需为了提问而进行有风险的操作（例如卸载清数据、清除账号信息或改动系统设置）。如果问题涉及数据或账号安全，先停止尝试并说明情况。

## 一份有用的问题报告

请尽量包含以下信息：

- **标题**：功能/设备 + 现象，例如“USB 独占：HA1 授权后开始播放失败”。
- **版本**：弥乐版本号，以及正式版或开发版。
- **设备环境**：手机型号、Android 版本；设备互联问题还需说明 DAC、转接头或接收设备型号。
- **复现步骤**：从打开哪个页面开始，依次做了什么。
- **预期结果**：你原本期望发生什么。
- **实际结果**：应用具体显示什么、是否有声音、何时发生。
- **复现频率**：每次发生、偶尔发生，还是只出现过一次。
- **排查情况**：已尝试哪些步骤，结果如何。
- **日志**：必要时附上从“设置 → 关于”导出的 MeloX 全部日志。

请用文字描述关键信息。截图或视频可作为补充，但不要只发一段无法看出操作步骤的视频。

## 可直接复制的模板

```text
标题：<功能或设备>：<简短现象>

弥乐版本：<例如 0.7.1 正式版 / dev-latest 开发版>
手机型号：
Android 版本：
相关音源/设备：<没有则写“不涉及”>

复现步骤：
1.
2.
3.

预期结果：
实际结果：
复现频率：<每次 / 偶尔 / 暂未复现>
已尝试的排查：

日志：<已附 / 未附；如果未附，说明原因>
```

## 不同问题的补充信息

### 播放或音源问题

- 说明音源、音质、歌曲是否登录可播；可用歌曲名帮助定位，但注意歌曲记录可能属于个人信息。
- 说明是搜索不到、解析链接失败、播放报错、无声还是播放中断。
- 第三方音源请说明脚本来源及大致版本；不要在公开 Issue 中贴 Cookie、令牌或含密钥的脚本配置。

### USB DAC 问题

- 提供手机、Android 版本、DAC 和 OTG 转接头型号。
- 说明系统是否弹出 USB 授权、弥乐选择的输出以及失败发生的步骤。
- USB 独占仍为实验性功能，目前不支持 UAC2、异步反馈、多事务端点和 DSD。请先对照 [USB 支持范围](usb-audio)。

### 局域网设备问题

- 说明发送端与接收端设备、连接的网络类型，以及双方是否处于同一个可互通的局域网。
- 说明是发现不到设备、连接失败、不同步还是播放中断。

## 日志与隐私

日志可能包含账号状态、歌曲信息、请求 URL、设备信息或第三方服务响应。URL 参数会尽力脱敏，但不要假设日志完全匿名。分享前请自行检查，删除不愿公开的信息；不要发布密码、Cookie、令牌、私有播放链接或个人联系方式。

更多说明见[隐私与日志](privacy-and-logs)。如果不能安全地公开日志，可以在 Issue 中先说明，并询问项目维护者是否有合适的私下提交渠道。

## 收到回复后

补充信息时请编辑原问题或在同一讨论串回复。问题解决后，简短说明最终原因和解决办法；这能帮助后来遇到相同问题的人，也方便维护者关闭问题。
